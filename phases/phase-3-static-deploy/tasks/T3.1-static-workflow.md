# T3.1 — Rewrite the deploy workflow for static assets

## Why this task exists

The current workflow still runs migrations, writes a secrets file, and rolls out a container. None of those
exist after Phase 2, and the build/deploy mode mismatch still blocks a prebuilt deploy.

## Pre-conditions

- Phase 2 merged: no API, container, D1, or migrations.
- A production domain and account id are known.

## What to do

1. Replace the build steps in both jobs with one pair:

   ```yaml
   - name: Build web
     run: pnpm turbo run build --filter=@blog/web
     env:
       PUBLIC_SITE_URL: ${{ vars.PUBLIC_SITE_URL }}

   - name: Build edge artefact
     working-directory: apps/edge
     run: pnpm exec cf build --mode production
   ```

2. Delete the migration step, the secrets writer, the cleanup step, and the `--secrets-file` /
   `--containers-rollout` flags. The deploy becomes:

   ```bash
   cd apps/edge && pnpm exec cf deploy --prebuilt --mode production
   ```

3. Extend the change filter:

   ```bash
   git diff --name-only "$BEFORE" "$GITHUB_SHA" \
     | grep -qE '^(apps/(edge|web)/|packages/|pnpm-lock\.yaml|turbo\.json)'
   ```

4. Remove the now-unused environment references (`D1_API_TOKEN`, `IP_HASH_SALT`, `SESSION_SECRET`,
   `SEND_EMAIL_FROM`, `CLOUDFLARE_D1_DATABASE_ID`) from the workflow and from any comments.

## Touches

- `.github/workflows/deploy-edge.yml`

## Verification

```bash
rg -n "d1 migrations|secrets.env|containers-rollout|D1_API_TOKEN|SESSION_SECRET" .github/workflows/
# expected: no matches
pnpm turbo run build --filter=@blog/web
cd apps/edge && pnpm exec cf build --mode production
pnpm exec cf deploy --prebuilt --mode production --dry-run
# expected: exit 0
```

The dry-run no longer needs Docker. It is the gate this phase exists to produce.

## Code style

- One build step per artefact, named after the action; no inline secrets.

## Risks

- A cached Turbo artifact can hide a missing `PUBLIC_SITE_URL`; clear `.astro`/`dist` before the check.
- `cf build` may reject a prebuilt artifact if the mode is not recorded; the dry-run proves it.
- Rollback: revert the workflow commit; no production change happens in this phase.

# T3.2 — Replace the config placeholders and scope the domain

## Why this task exists

The Worker config still carries a placeholder account id, a production domain applied in every mode, and
bindings that belonged to the container. A preview deploy must not claim the production hostname.

## Pre-conditions

- T3.1 removed the container/D1 code paths.
- Account id, production domain, and the preview origin are known.

## What to do

1. Replace `accountId` with the real account id, and make the hostname production-only:

   ```ts
   ...(isProd
     ? { domains: ["<domain>"] }
     : {}),
   ```

2. Remove the `/api/*` trigger if any remains; the Worker serves all asset paths.
3. Keep the observability block, the compatibility date/flags, and the asset configuration.
4. Prove both evaluations and the production dry-run:

   ```bash
   cd apps/edge && pnpm exec cf build --mode staging --dry-run
   cd apps/edge && pnpm exec cf build --mode production --dry-run
   pnpm exec cf deploy --prebuilt --mode production --dry-run
   ```

5. Confirm the built site names the real origin:

   ```bash
   rg -o "https://[a-z0-9.-]+" apps/web/dist/vi/index.html | sort -u | head
   # expected: the production domain, never example.com
   ```

## Touches

- `apps/edge/cloudflare.config.ts`
- GitHub environment variable `PUBLIC_SITE_URL` (and the account id if kept there)

## Verification

```bash
rg -n "<[A-Z_]+>|example\.com" apps/edge/cloudflare.config.ts
# expected: no matches
```

Both mode evaluations and the production dry-run must exit 0. A placeholder in a bound value is a failure;
one in a comment is acceptable.

## Self-review

- [ ] No placeholder in a bound value.
- [ ] Preview resolves no production domain.
- [ ] Production resolves exactly one domain.
- [ ] The built HTML and feeds carry the real origin.
- [ ] No D1/container binding remains.

## Code style

- Comments state why the domain is mode-scoped.

## Risks

- A conditional `domains` key can change the config type; the dry-run catches it.
- A stale `dist` can make the origin check pass against an old build; rebuild first.
- Rollback: revert the config commit; the domain claim is removed with it.

# T1.2 — Remove the page, nav entry, copy, island, and contact e2e test

## Why this task exists

With the route deleted, the contact page becomes a dead-end form. This task removes the visible surface
and the test that asserts it, in the same release as T1.1.

## Pre-conditions

- T1.1 specifies the exact route removal.
- Nav and footer are the only inbound links; confirm with a grep before deleting the page.

## What to do

1. Delete `apps/web/src/pages/[lang]/contact.astro` and `packages/ui/src/ContactForm.vue`.

2. Remove the navigation entry. Evidence:

   ```ts
   // i18n.ts — delete the `contact` nav label, the `contactTitle` /
   // `contactLead` / `contactExpectTitle` / form labels, and contactPath().
   // Nav.astro / Footer.astro — remove the link that uses contactPath(lang).
   ```

3. Delete the `CONTACT` block from `apps/web/src/lib/pages-content.ts`, and any `contact` reference in
   `BaseLayout.astro` (alternates or structured data).

4. Delete `e2e/contact-form.spec.ts` and remove the contact recorder and `contactStatus` from
   `e2e/fixtures.ts`. Keep the views recorder.

5. Check the built output and the static journey:

   ```bash
   pnpm --filter @blog/web build
   rg -i "contact" apps/web/dist
   # expected: no page, no nav link, no string
   ```

   Do not add a redirect from `/vi/contact/` unless the owner asks; a 404 is the honest result.

6. Keep layout, spacing, typography, and motion untouched everywhere else. This is removal, not a
   redesign; no visual change is requested.

## Touches

- `apps/web/src/pages/[lang]/contact.astro` (delete)

```bash

# expected: no matches
```

The e2e suite is the only automated proof that navigation has no dead link; run it, do not infer from the
build.

- A missing nav removal leaves a 404 link; the e2e static journey and the `dist` grep catch it.

  signal, not a reason to keep the key.
- Rollback: revert the commit; the page and form return with the route from T1.1.

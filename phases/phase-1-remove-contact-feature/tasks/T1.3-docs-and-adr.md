# T1.3 — Update docs, contract, and ADR-0011

## Why this task exists

The docs and the HTTP contract still describe a contact endpoint and a notification email. After T1.1
and T1.2 they would be false, and the decision to drop the whole surface needs a durable record.

## Pre-conditions

- T1.1 and T1.2 specify the removed symbols and files.

## What to do

1. Add `docs/adr/0011-remove-contact-feature.md`, Accepted 2026-11-19:
   context (no newsletter exists; delivery was best effort; one extra secret and failure path; the owner
   does not want the channel), decision (delete the surface; keep the applied migration and dormant
   table), consequences (no inbound channel; existing rows remain; a future export/purge is a separate
   decision), `Supersedes ADR-0008`. Set `0008`'s status to `Superseded by ADR-0011` and add the index row.

2. Remove the contact path, schemas, and examples from `docs/api/openapi.yaml`. Remove the error rows that
   only the contact route produced (400 bind failure, 429 rate limit, 413 if it becomes unreachable) from
   `docs/api/error-codes.md`; keep 422 for the views slug and 500/503.

3. Retire `docs/features/contact-form.md` and its index row. A removed feature's document is deleted with
   the code rather than archived.

4. Update the architecture set: remove the contact actor/edge, binding row, flow §4, email partner,
   deployment environment row, glossary entries, crosscutting rate-limit and PII claims, and the quality
   scenario that asserted 429.

5. Update `docs/status.md`: the contact feature is removed, P0-4 (`SEND_EMAIL_FROM`) is obsolete, and the
   dormant table becomes a new ranked item (retention/export of existing rows).

6. Update `docs/development/environment-variables.md` (no email, rate limit, or salt), the operations pages
   and runbooks (no contact failure symptom, no email in the deploy secrets), and the root `README.md`.

7. Confirm no doc still promises a contact channel:

   ```bash
   rg -in "contact|send_email|SEND_EMAIL_FROM|notification email" docs README.md SECURITY.md
   # expected: only ADR-0008/0011 history and the migration/table description
   ```

# T4.1 — Deploy preview and run the smoke set

## Why this task exists

A green build proves the files exist, not that Cloudflare serves them with the right origin, headers, and
404 behaviour. The preview is where those claims become evidence.

## Pre-conditions

- Phase 3 merged; the dry-run exits 0; the preview origin is known.

## What to do

1. Build and deploy the preview mode:

   ```bash
   PUBLIC_SITE_URL=https://<preview-origin> pnpm turbo run build --filter=@blog/web
   cd apps/edge && pnpm exec cf build --mode staging
   pnpm exec cf deploy --prebuilt --mode staging
   ```

2. Fetch each route class and record the status and a content fragment:

   ```bash
   for p in /vi/ /en/ /vi/posts/ /en/posts/ /vi/tags/ /vi/about/ /vi/search/ \
            /vi/rss.xml /en/feed.json /sitemap-index.xml /does-not-exist; do
     printf '%s ' "$p"; curl -s -o /dev/null -w '%{http_code}\n' "https://<preview-origin>$p"
   done
   ```

   Expected: 200 for real routes, 404 for the unknown path (`notFoundHandling: "404-page"`).

3. Check the origin and headers:

   ```bash
   curl -s https://<preview-origin>/vi/rss.xml | head -20
   curl -sI https://<preview-origin>/vi/ | grep -Ei 'strict-transport|x-content-type|x-frame'
   ```

   Links must name the preview origin; all three headers must be present.

4. Run one search query in a browser and open a result.

## Touches

- Preview Worker only

## Verification

Every route's status and the header output are attached. A 200 from `/vi/` alone is not a smoke.

## Self-review

- [ ] Real routes 200, unknown path 404.
- [ ] Canonical/feed URLs use the preview origin, not `example.com`.
- [ ] HSTS, nosniff, and frame deny present.
- [ ] Search opens a post.
- [ ] No `/api/*` request is made by any page.

## Code style

- Commands are copy-pasteable; the origin is substituted once.

## Risks

- Testing the production domain from the preview step proves nothing about preview mode.
- A CDN cache can serve a stale 404; use a cache-busting query if a route looks wrong.

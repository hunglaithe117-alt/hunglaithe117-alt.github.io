# T2.1 — Delete the API, D1 wiring, and Go tooling

## Why this task exists

`apps/api` exists only for the view counter, which is being removed. Keeping the module, its Dockerfile,
migrations, and Go CI leaves dead code that still costs build time and reviewer attention.

## Pre-conditions

- Q6 answered: no production D1 needs an export, or it has been exported.
- T2.2 is prepared so the counter leaves in the same release.

## What to do

1. Delete the module and its workspace wiring:

   ```bash
   rm -rf apps/api
   rm -f go.work go.work.sum
   ```

2. Remove Go from the pipeline:

   - `.github/workflows/ci.yml`: delete the `setup-go` step, the `go.sum` cache shim, and the
     `govulncheck` step from the security job.
   - `package.json`: delete `security:govulncheck`.
   - `turbo.json`: remove `go.work` from `globalDependencies`, remove the `db:migrate` task, and drop
     `bin/**` from `build.outputs` if nothing writes it.
   - `.gitignore`: remove the Go build-output comment/entry if it becomes misleading.

3. Update the lockfile after the workspace package disappears:

   ```bash
   pnpm install
   ```

4. Keep `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` for the asset deploy; remove any D1-specific
   task env (`db:migrate`) and comments.

## Touches

- `apps/api/**` (delete), `go.work`, `go.work.sum` (delete)
- `.github/workflows/ci.yml`, `package.json`, `turbo.json`, `.gitignore`, `pnpm-lock.yaml`

# T2.5 — Rewrite the docs for a static site

## Why this task exists

The documentation still describes an API, a container, D1, and a view counter. After T2.1–T2.4 those are
false, and a reader would look for code that no longer exists.

## Pre-conditions

- T2.1–T2.4 specify exactly what is deleted.

## What to do

1. Add `docs/adr/0012-static-site-with-assets-only-worker.md`, Accepted 2026-11-19:
   context (no runtime need), decision (static build, thin Worker, no API/container/D1), consequences
   (no view counts/contact; simpler deploy; headers stay in code), `Supersedes ADR-0005, ADR-0006,
ADR-0007`; note that it partially supersedes ADR-0010 (the `slog` half). Update those records'
   status lines and the ADR index.

2. Delete the API documentation family: `docs/api/**`. Remove the `api/` row from `docs/README.md` and
   every link into it.

3. Architecture:

   - `02-container-view.md`: one container (Worker + static assets); delete D1, container runtime and
     Durable Object rows/edges.
   - Delete `03-component-view.md` (the API was the only component-heavy container) and
     `06-data-architecture.md` (no persistent data). Remove them from the index and all links.
   - `04-runtime-flows.md`: keep the page/asset flow and the 404 path; delete the view flow and the API
     branches; keep the "no authentication" note.
   - `05-deployment-view.md`: remove container, D1, email and migrations; keep local/preview/production
     and the VPS note (static files only).
   - `07`, `08`, `09`: remove view-count scenarios, persistence/rate-limit/error-envelope concepts, and
     the D1/view/container glossary terms; keep i18n, logging, configuration, headers.
   - `01`: remove D1 and "dynamic surface" language.

4. Features: delete `view-counter.md`; the index keeps only the content pipeline.

5. Development: remove Go/API/D1 from `local-setup.md`, `environment-variables.md`, `testing-guide.md`,
   and `coding-rules/README.md`. Local setup becomes: install, build web, preview; edge after build.

6. Operations: rewrite `ci-cd-pipeline.md` for a static deploy (no migrations, no secrets, no container);
   `monitoring-and-alerts.md` keeps Worker logs and uptime only; `disaster-recovery.md` becomes
   "rebuild and redeploy the last commit" with no data restore; delete the API runbooks and keep
   `edge-deploy-fails.md`; update the runbooks index and the operations index.

7. `docs/status.md`: rewrite the feature matrix (static site only), replace the P0 list with the static
   deploy blockers (mode, `PUBLIC_SITE_URL`, account/domain placeholders), remove D1/API defects, and
   update the VPS section.

8. `README.md`: remove the API, container, D1, types, and view-counter bullets; describe build → deploy.

9. `SECURITY.md`: add a dated note that the API, container, D1 and view counter were retired by ADR-0012,
   so API-specific findings are historical.

## Risks

- Deleting chapters leaves cross-links broken; the link check is the gate.
- ADR immutability: only status lines change on 0005/0006/0007/0010.
- A rewritten operations page can lose a real procedure; carry over anything still true (deploy, logs,
  rollback) before deleting.

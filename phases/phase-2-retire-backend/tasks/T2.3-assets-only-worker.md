# T2.3 — Make the Worker serve assets only

## Why this task exists

The edge Worker still declares a container, a Durable Object, D1 bindings, and an `/api/*` branch. With
the API gone, those declarations either fail the build or ship an unused runtime.

## Pre-conditions

- T2.1 deletes the container image and T2.2 removes the last route consumer.

## What to do

1. Delete `apps/edge/src/api-container.ts` and its `export { Api }`.
2. Reduce `cloudflare.config.ts`:
   - remove `defineContainer`, `containers`, `exports`, and the `API` Durable Object binding;
   - remove `DB`, `D1_DATABASE_ID`, `D1_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` bindings;
   - keep `ASSETS`, the domain (production only), observability, and the compatibility date/flags.
3. Make the Worker run for every path so the headers still apply:

   ```ts
   // VERIFY the supported value with the pinned cf:
   //   cd apps/edge && pnpm exec cf cli search "run worker before assets"
   assets: { runWorkerFirst: ["/*"], notFoundHandling: "404-page" }
   ```

   If `cf` cannot run the Worker for all asset paths, choose one: deploy pure assets and move the headers
   to `apps/web/public/_headers` (Q8), or accept that headers only apply to 404 fallbacks. Record which.

4. Simplify `src/index.ts` to one job:

   ```ts
   export default {
     async fetch(request: Request, env: EdgeBindings): Promise<Response> {
       return withSecurityHeaders(await env.ASSETS.fetch(request));
     },
   };
   ```

   Delete the `/api` branch, the 503 guard, and the container import. Update `EdgeBindings` to
   `{ ASSETS: Fetcher }` (the type package is deleted in T2.4; define it locally or delete it).

5. Build without Docker and inspect the output:

   ```bash
   pnpm --filter @blog/web build
   cd apps/edge && pnpm exec cf build --mode production
   ```

## Touches

- `apps/edge/src/index.ts`, `apps/edge/cloudflare.config.ts`
- `apps/edge/src/api-container.ts` (delete)
- `apps/edge/wrangler.config.ts` if the asset directory changes

## Verification

```bash
cd apps/edge && pnpm exec cf build --mode production
# expected: exit 0, no Docker requirement, no container in the output
rg -n "Container|durableObject|D1|API:|CLOUDFLARE_ACCOUNT_ID|D1_API_TOKEN" apps/edge
# expected: no matches
```

Then serve the built output through `cf dev` (or the asset preview) and confirm a page returns with
`Strict-Transport-Security` and `X-Content-Type-Options` present.

## Risks

- `runWorkerFirst: ["/*"]` may not be the supported selector; verify with the CLI before relying on it.
- A pure-assets deploy without `_headers` silently loses HSTS and friends; that is a regression, not a
  simplification.
- Rollback: revert the commit; the container config returns (but the API code is gone, so revert T2.1 too).

# T3.2 — task memory

Completed 2026-11-19.

## What changed

`apps/edge/cloudflare.config.ts`:

- `accountId` is no longer a committed placeholder. It is read from `CLOUDFLARE_ACCOUNT_ID` and omitted
  when unset, so `cf` resolves it (CI variable, `cf auth login`, or the process environment).
- The production domain is `SITE_DOMAIN`, claimed only when `mode === "production"` **and** the value is
  set. `example.com` is gone from the config.
- `isProd` is now strict (`mode === "production"`); `undefined` no longer counts as production, so a
  mode-less build cannot claim the production hostname. The worker name for a mode-less build became
  `blog-edge-default`.

`turbo.json`: `SITE_DOMAIN` declared as an `@blog/edge#build` env input (identity input under strict
`envMode`).

`.env.example`: documents the two edge identifiers and states that `cf` does not expose `.env` values to
the config — they must be exported.

## Evidence

```text
$ cf build --mode production                       (no env)     -> exit 0
  config.json: {"buildContext":{"isPreview":false,"mode":"production"}}
$ cf deploy --prebuilt --mode production --dry-run  (no env)     -> exit 0

$ CLOUDFLARE_ACCOUNT_ID=0123... SITE_DOMAIN=blog.example.test cf build --mode production
  config.json: {"accountId":"0123456789abcdef0123456789abcdef","buildContext":{...,"mode":"production"}}
  worker.config.json contains "blog.example.test"

$ SITE_DOMAIN=blog.example.test cf build --mode staging
  -> "blog.example.test" absent from .cloudflare/**   (preview claims no production domain)

$ rg -n "<[A-Z_]+>|example\.com" apps/edge/cloudflare.config.ts
  -> no matches
```

Turbo path: `SITE_DOMAIN=... CLOUDFLARE_ACCOUNT_ID=... pnpm turbo run build --filter=@blog/edge --force`
produced a production-mode artefact with both values, proving strict `envMode` passes them through.

## Deviation from the plan

The plan expected the account id to be committed ("safe to commit"). It is read from the environment
instead: the owner has not supplied it yet (Q9), and an env-sourced value keeps the repository free of
account-specific identifiers while leaving `cf`'s own resolution path intact.

## Not verified

`cf` was not pointed at a real account: no credentials exist on this machine, and the dry-run is
deliberately credential-free. The domain claim (`domains: [...]`) is therefore proven at config-evaluation
level only, not against Cloudflare DNS.
